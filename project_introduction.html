项目作品介绍书 / 架构说明文档

知程 (Anno2Agenda)

基于 Flutter 与端侧大模型的跨平台无感通知转日程与算力协同系统
目标平台：Android / Windows
核心框架：Flutter + llama.cpp (FFI)
端侧模型：Qwen3.5 GGUF + 中文规则引擎
文字采集：无障碍节点树直读 + ML Kit OCR
跨端通信：局域网 HTTP 协同 (Port 9527)
运行特性：全离线可用 / 数据不出内网

一、项目背景与问题提出

在日常学习、科研与办公场景中，各类通知公告高度碎片化地分布在即时通讯群聊（微信、QQ、飞书、企业微信）、高校教务网站、电子邮件、公众号推文、线下活动海报以及长达数小时的线上视频会议速记中。面对高频、多源、非结构化的繁杂通知，用户在将其转化为个人日程管理时普遍面临以下四个核心痛点：

  1. 跨应用手动录入极度繁琐、效率低下：用户需要在聊天软件或网页与系统日历之间反复切换窗口，逐字核对并手动输入事项名称、起止时间、会议室地点及待办要求。操作链路冗长，极易在繁杂消息轰炸中遗漏关键时间节点。
  2. 传统正则表达式与规则引擎机械截断、准确率低：现有部分日程提取工具依赖固定正则表达式匹配。当遇到带有语境转折、变更通知或复杂修饰的文本（例如：“原定于周三下午3点在科技楼402的组会，因临时检查推迟到本周五下午2点半改在逸夫楼B305举行”）时，规则引擎往往机械截取第一个作废时间或截断残缺地点，导致生成的日程严重失真。
  3. 云端大模型方案存在隐私合规风险与网络依赖：若将内部会议纪要、未公开科研课题通知或个人行程上传至第三方公有云大模型 API 进行解析，不仅需要持续消耗商业 Token 费用，更存在敏感数据外泄风险，且在弱网或离线环境下完全失效。
  4. 移动端直接处理超长文本易触发内存溢出 (OOM)：手机端可用运行内存（RAM）与散热受限，当直接将数万字的视频会议全场字幕或长篇教务公文输入手机本地大模型时，KV Cache 显存占用急剧飙升，极易引发推理进程崩溃或系统卡死。

针对上述问题，本项目设计并实现了“知程 (Anno2Agenda)”——一款完全运行于终端本地、兼顾深度语义理解与跨端算力互助的无感通知转日程系统，实现从“看到通知”到“静默写入系统日历并设置提醒”的闭环体验。

二、系统技术架构

系统整体采用“Flutter 跨平台统一业务层 + 原生平台桥接采集层 + llama.cpp 端侧混合推理层 + 局域网跨端算力互助层”的四层架构设计，同时支持 Android 移动端与 Windows 桌面端原生编译运行。

图 1：知程 (Anno2Agenda) 跨平台系统分层技术架构图

（一）基于 Flutter 的跨平台统一架构与原生扩展

前端交互与核心调度逻辑基于 Flutter 框架构建，通过一套 Dart 核心代码库同时编译生成 Android 客户端与 Windows 桌面端原生可执行程序。针对不同终端的屏幕形态，界面层实现了自适应三栏（桌面宽屏）、双栏（平板/小窗）与单栏（手机端）布局。在 Android 侧，通过 MethodChannel 深度桥接 Kotlin 原生服务（FloatingBubbleService 与 ScreenCaptureAccessibilityService），将全局贴边悬浮窗、无障碍窗口节点遍历、Android 11+ 静默截屏与 Google ML Kit 离线中文 OCR 能力无缝注入 Flutter 业务流。

（二）基于 llama.cpp 的端侧大模型运行框架与混合推理

为彻底摆脱云端 API 依赖，系统内嵌了基于 C/C++ 的高性能端侧推理框架 llama.cpp（支持 Qwen3.5 Gated DeltaNet 混合注意力架构与 Vulkan 移动端 GPU 硬件加速）：

  • 移动端直接推理：Android 端通过 Dart FFI 直接挂载量化后的 Qwen3.5-0.8B (Q4_K_M, 约 530MB) 或 Qwen3.5-2B GGUF 模型文件，并内置连接国内魔搭社区 (ModelScope) 直链的“模型管家”，支持断点续传下载、模型热切换与空间释放。
  • 桌面端守护进程协同：Windows 端自动检测并静默拉起本地 llama-server 或 Ollama 守护进程，自动绕过系统全局代理直连本机回环接口，利用桌面级 CPU/GPU 提供高吞吐推理。
  • 双引擎协同与确定性兜底：系统内置一套零延迟中文时空语义规则引擎（AiExtractorService）。大模型负责复杂语境消歧、改期通知过滤与 JSON 结构化生成；规则引擎提供精确的相对日期换算（如“下周三”“本周日晚8点”）、农历转换及毫秒级离线兜底。

三、核心应用场景

1. 高校教务与课程变动通知处理

面对教务系统、班级群中频繁发布的调课通知、考试安排、选课退补选截止时间及实验验收通知，学生在当前聊天页面点击贴边悬浮窗即可 0ms 提取屏幕文字，自动剔除“原定时间”等干扰信息，一键写入手机日历并设置提前半小时提醒。

2. 学术讲座海报与竞赛活动报名

针对微信公众号推文中的学术报告海报、校园招新或竞赛宣讲图片，由于无法直接复制文字，用户可通过悬浮窗触发“静默截屏 + 离线中文 OCR”，在本地完成图片文字识别与大模型结构化提取，自动归纳讲座时间、报告厅地点与签到要求。

3. 超长视频会议字幕与研讨会速记提炼

在长达数小时的线上学术研讨会或项目周会后，针对数万字的会议语音转写字幕，手机端可通过局域网算力协同机制将长文本推流至同一 Wi-Fi 下的 Windows 电脑端，由桌面端大模型快速提炼出多项关键截止日期与后续会议安排并回传手机。

4. 涉密、内网与离线办公日程管理

在实验室内部网络、政企内网或差旅飞行等断网场景下，系统无需连接任何外部云服务器即可完成从采集、OCR、LLM 推理到日历入库与双端局域网同步的全流程，并借助系统日历生态无缝联动手机灵动岛、智能手环与智能手表震动提醒。

四、项目主要创新点

  1. 端侧大模型 (LLM) 与中文时空规则双引擎混合架构： 突破了传统日程软件“纯正则规则死板易错”与“纯云端大模型高延迟、重网络”的两难局限。通过端侧 Qwen3.5 GGUF 模型深度理解复杂通知中的改期、顺延、条件转折与携带物品清单（Checklist），再配合 0ms 中文时空语义规则引擎校准相对日期与节假日，兼顾了语义高准确率与毫秒级响应速度。
  2. 局域网跨端算力互助机制（手机投喂、电脑推理）： 创新性地设计了基于内网端口 9527 的端侧算力协同协议（/extract）。当手机端面对数万字超长会议字幕或复杂公文等高负载任务时，无需担心移动端内存溢出（OOM）或发热降频，可一键将文本流式卸载至局域网内的 Windows 电脑端，利用桌面端满血模型高速推理后再将轻量级结构化 JSON 秒级回传手机。
  3. Android 零跳转全局悬浮窗与 0ms 无障碍节点树直读： 重构了移动端通知转日程的交互范式。用户无需离开当前正在浏览的微信、QQ 或网页，点击贴边悬浮胶囊即可原地展开卡片；优先通过 Android AccessibilityService 直接遍历 UI 节点树提取文字（0 延迟、0 额外截图开销），仅在遇到纯图片海报时自动切换至静默截屏与离线 OCR，并直接调用原生 CalendarContract 静默入库，真正实现“零跳转”闭环。
  4. 全链路数据不出内网的隐私安全与多端硬件生态联动： 从屏幕文字采集、离线 OCR、GGUF 本地模型推理，到手机与电脑之间的日程双向去重同步（/sync），100% 在用户本地设备与局域网内闭环完成，杜绝任何云端隐私泄露风险；同时通过直接写入系统级原生日历数据库与标准 RFC 5545 (.ics) 协议，天然打通系统级灵动岛弹窗、智能手表及手环的跨设备提醒能力。
